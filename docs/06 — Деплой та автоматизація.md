# 06 — Деплой та автоматизація

## Локальний запуск

```bash
# Клонувати і встановити залежності
tar -xzf trend-finder.tar.gz
cd trend-finder
npm install

# Налаштувати змінні середовища
cp .env.example .env.local
# Редагувати .env.local — додати APIFY_API_TOKEN

# Запустити dev сервер
npm run dev
```

Відкрити: `http://localhost:3000`

> **Без APIFY_API_TOKEN** — додаток запускається в Demo Mode з тестовими даними.
> DemoBanner відображається у верхній частині сторінки.

## Деплой на Vercel

### 1. Підключити репозиторій

```bash
# Через Vercel CLI
vercel deploy

# Або через vercel.com → Import Git Repository
```

### 2. Встановити змінні середовища

Vercel Dashboard → Settings → Environment Variables:

| Змінна | Значення | Середовище |
|---|---|---|
| `APIFY_API_TOKEN` | `apify_api_...` | Production, Preview |
| `UPSTASH_REDIS_REST_URL` | `https://...upstash.io` | Production |
| `UPSTASH_REDIS_REST_TOKEN` | `AX...` | Production |

> ⚠️ **Ніколи не додавати `NEXT_PUBLIC_` префікс** до цих змінних.

### 3. Оновити rate limiting для Production

Замінити in-memory rate limiter на Upstash в `src/app/api/search/route.ts`:

```typescript
// Встановити пакети
// npm install @upstash/ratelimit @upstash/redis

import { Ratelimit } from "@upstash/ratelimit";
import { Redis } from "@upstash/redis";

const ratelimit = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(10, "1 m"),
  analytics: true,
});

// Замінити checkRateLimit(ip) на:
const { success } = await ratelimit.limit(ip);
if (!success) return NextResponse.json({ error: "Too many requests" }, { status: 429 });
```

**Чому Upstash?** Vercel запускає Edge Functions в різних інстансах. In-memory Map не шариться між ними — rate limit не буде працювати коректно.

## Upstash (безкоштовний tier)

1. Зареєструватись на `console.upstash.com`
2. Create Database → Region: EU West (або найближчий)
3. Скопіювати `UPSTASH_REDIS_REST_URL` і `UPSTASH_REDIS_REST_TOKEN`
4. Встановити в Vercel Environment Variables

**Free tier:** 10,000 команд/день — достатньо для MVP.

## Чекліст перед деплоєм

- [ ] `npm run build` проходить без помилок
- [ ] `npm run type-check` — 0 помилок TypeScript
- [ ] `.env.local` не закомічено у git (є в `.gitignore`)
- [ ] `APIFY_API_TOKEN` встановлено у Vercel
- [ ] `next.config.ts` містить всі потрібні `remotePatterns` для зображень
- [ ] Rate limiting протестовано (> 10 req/min → 429)
- [ ] Demo mode перевірено (без токена — banner відображається)

## Автоматизація (V3)

На поточному етапі — ручний запуск через браузер. Для V3 планується:

### Cron (Vercel Cron Jobs)

```json
// vercel.json
{
  "crons": [{
    "path": "/api/trending-refresh",
    "schedule": "0 6 * * *"
  }]
}
```

```typescript
// src/app/api/trending-refresh/route.ts
export async function GET() {
  // Попередньо кешувати популярні запити:
  // "wireless earbuds", "smart watch", "led strip"
  // Зберігати в Redis з TTL 24h
}
```

### Сповіщення про зміну цін (V3)

```
[Cron щогодини] → [Запит до Apify] → [Порівняти з Redis кешем]
                                           → [Якщо ціна змінилась → Telegram webhook]
```

## Логування

Поточне логування через `console.error` у Route Handler:

```typescript
console.error("[/api/search] Error:", message);
```

Vercel автоматично збирає logs → Dashboard → Functions → Logs.

Для production рекомендується додати structured logging:

```typescript
console.error(JSON.stringify({
  timestamp: new Date().toISOString(),
  route: "/api/search",
  error: message,
  query,
  ip,
}));
```

## Крайні випадки

| Ситуація | Поведінка |
|---|---|
| Vercel cold start | Перший запит повільніший (нормально) |
| Apify недоступний | 502 → UI показує ErrorState з retry |
| Redis недоступний | Якщо rate limiter впав — fallback без обмежень (треба handle) |
| `next.config.ts` без домену | next/image відхиляє зображення |
| `.env` закомічено | GitHub secret scanning — видалити та rotate токен |
